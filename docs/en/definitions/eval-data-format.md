# Navigation Evaluation Data Format

This document defines the Episode format and trajectory data format for embodied navigation evaluation data.

!!! info "Relationship to Training Data Format"
    The evaluation data format is a **subset** of the Episode structure in the [training data format](nav-data-format.md). The evaluation framework (navarena-bench) consumes this format directly. Training data is generated by navarena-gen and includes additional metadata and files (e.g. goal_images, rendered_videos), but the core Episode fields are consistent with this specification.

## 1. Top-Level Dataset Format

`metadata.task_types` contains one or more task types; `metadata.splits` contains one or more split names.

```json
{
  "version": "1.0.0",
  "dataset_name": "navarena_bench",
  "metadata": {
    "created_date": "2026-01-14",
    "description": "NavArena general embodied navigation dataset",
    "task_types": ["pointnav", "imagenav", "objectnav", "vln"],
    "total_episodes": 100,
    "splits": ["train", "val_seen", "val_unseen", "test"]
  },
  "episodes": []
}
```

## 2. Episode Core Field Definitions

### 2.1 Required Fields

| Field | Type | Description |
|-------|------|--------------|
| `episode_id` | string | Unique identifier, format: {split}\_{index}, e.g. "train_001" |
| `scene_path` | string | Scene path, e.g. "x2robot/17dc3367" (relative to $NAVARENA_DATA_DIR/assets/) |
| `task_type` | string | Task type: "pointnav" \| "imagenav" \| "objectnav" \| "vln" |
| `start_state.position` | [x, y, z] | Start position |
| `start_state.rotation` | [qx, qy, qz, qw] | Start rotation quaternion |
| `goals` | array | Goal list, at least one goal required |

### 2.2 Optional Fields

| Field | Type | Description |
|-------|------|--------------|
| `split` | string | Dataset split: "train" \| "val_seen" \| "val_unseen" \| "test" |
| `instructions` | array | Instruction list (required for VLN tasks) |
| `gt_path` | object | Ground Truth trajectory info |

## 3. Goals Field Format (by goal_type)

### 3.1 Position Type (Point Navigation)

`position` is the goal position [x, y, z]; `rotation` is the optional goal orientation [qx, qy, qz, qw].

```json
{
  "goal_type": "position",
  "position": [5.0, 3.0, 0.0],
  "rotation": [0.0, 0.0, 0.383, 0.924]
}
```

### 3.2 Image Type (Image Navigation)

`image_goal.image_path` is the goal image path. `position` and `rotation` are optional ground truth for evaluation.

```json
{
  "goal_type": "image",
  "image_goal": {
    "image_path": "goal_images/train_000001_goal.jpg"
  },
  "position": [-0.9, -0.5, 0.0],
  "rotation": [0.0, 0.0, -0.383, 0.924]
}
```

### 3.3 Object Type (Object Navigation)

`object_category` is the target object category; `object_id` is the optional instance ID; `position` is the optional object position for evaluation.

```json
{
  "goal_type": "object",
  "object_category": "table",
  "object_id": "table_0",
  "position": [-2.78, -1.57, -0.50]
}
```

## 4. Instructions Field Format (VLN Tasks)

`instruction_text` is the natural language instruction; `language` is the language code (e.g. "zh-CN", "en-US").

```json
{
  "instruction_text": "Go to the end of the hallway, turn left and find the table",
  "language": "en-US"
}
```

## 5. GT Path Field Format

`trajectory_file` is the GT trajectory file path. In `stats`: `geodesic_distance` (meters) and `num_steps` are required; `euclidean_distance`, `total_time`, `num_waypoints` are recommended; `avg_speed`, `max_speed` are optional.

```json
{
  "gt_path": {
    "trajectory_file": "gt_trajectories/train_001_gt.json",
    "stats": {
      "geodesic_distance": 5.83,
      "num_steps": 12,
      "euclidean_distance": 5.2,
      "total_time": 11.66,
      "num_waypoints": 8
    }
  }
}
```

## 6. GT Trajectory File Format

File path: `gt_trajectories/{episode_id}_gt.json`. Each trajectory step includes `step` (from 0), `position`, `rotation`, `timestamp`, `action`, `action_id`. Top-level `actions` and `action_names` are optional.

```json
{
  "episode_id": "train_000001",
  "trajectory": [
    {
      "step": 0,
      "position": [0.0, 0.0, 0.0],
      "rotation": [0.0, 0.0, 0.0, 1.0],
      "timestamp": 0.0,
      "action": "start",
      "action_id": 0
    }
  ],
  "actions": [0, 1, 2],
  "action_names": ["start", "forward", "turn"]
}
```

## 8. File Organization

Evaluation data uses the same hierarchical structure as training data, organized by scene and task type:

```bash
$NAVARENA_DATA_DIR/
├── datasets/                        # Or custom data root
│   └── {dataset_name}/
│       └── {dataset}/{scene_id}/    # e.g. x2robot/17dc3367
│           └── {task_type}/         # pointnav | imagenav | objectnav | vln
│               ├── train.json       # Episodes file
│               ├── val.json
│               ├── gt_trajectories/
│               │   ├── train_000000_gt.json
│               │   └── ...
│               └── goal_images/     # ImageNav goal images
│                   └── train_000000_goal.jpg
└── assets/                          # V1 format scene assets
    └── x2robot/
        └── 17dc3367/
            ├── manifest.json
            ├── aligned.ply
            ├── nav_map.pgm
            ├── nav_map.yaml
            ├── nav_mask.png
            └── labels.json          # optional
```

**Note**: `scene_path` in episodes is a relative path (e.g., `x2robot/17dc3367`), resolved by the evaluation framework using `$NAVARENA_DATA_DIR/assets/`.

## 9. Notes

- All paths use relative paths; data files must be organized according to **Section 8**.
- Quaternion format is consistently `[qx, qy, qz, qw]`.
